# Database Setup

Commercor uses one PostgreSQL schema shared by the Admin and Customer APIs. TypeORM synchronization must remain disabled; schema changes are made only through migrations in `admin-api/src/migrations`.

## New installation

1. Create an empty UTF-8 PostgreSQL database and a least-privilege owner. Do not restore application data into it.
2. Set `DB_TYPE=postgres`, `DB_HOST`, `DB_PORT`, `DB_USERNAME`, `DB_PASSWORD`, and `DB_NAME` for both APIs. Do not commit environment files.
3. Build the Admin API:

   ```powershell
   npm.cmd run build
   ```

4. From `admin-api`, apply and verify migrations:

   ```powershell
   node node_modules\typeorm\cli.js -d dist\utils\migrationDataSource.js migration:run
   node node_modules\typeorm\cli.js -d dist\utils\migrationDataSource.js migration:show
   ```

5. Confirm every entry is `[X]`, start both APIs, and check `GET /api/admin/health` and `GET /api/health`.
6. Create the first administrator through a controlled bootstrap procedure. No administrator or default password is seeded by the schema migration.

## Existing installations

Older installations obtained their core schema from the former `synchronize=true` configuration and therefore have the later 20 migration records but no baseline record. Before upgrading:

1. Take and verify a database backup.
2. Run `migration:show`; the baseline and any newer corrective migrations should appear pending.
3. Run the normal `migration:run` command. The baseline checks all 20 expected legacy tables. If all exist, it makes no schema changes and TypeORM records it. If any—but not all—exist, it aborts with the missing-table list so the partial schema can be investigated safely.
4. The index corrective migration uses `CREATE INDEX IF NOT EXISTS` and does not alter business rows.
5. Run `migration:show` again and smoke-test both APIs.

Do not manually mark the baseline applied on an incomplete schema. Do not run the baseline `down()` on an existing installation. It is guarded by `ALLOW_BASELINE_DOWN=true` and is intended only for disposable databases where all later migrations have already been reverted.

## Baseline boundary

`InitialSchema1786224000000` reproduces the schema generated by the original entities at repository commit `99980c1`, immediately before `AddProductFilterCategories1786310400000`. It creates the 20 original tables, their primary/unique constraints, eight explicit indexes, fourteen foreign keys, timestamp columns, and UUID defaults. All commerce, rewards, payment hardening, coupon, variant, review, wishlist, tracking, notification, invoice, inventory, reset-token, cart, promotion, CRM, and analytics changes remain in their later migrations.
